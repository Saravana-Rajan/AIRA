## Fixed demo data and spoken-hint rule

- **Demo SKU ids** must be identical everywhere: in `content/catalog/murugan_dairy.json`, in the vision prompts and in the tests:
  `aavin_milk_500ml`, `aavin_milk_1l`, `sakthi_curd_500ml`, `sakthi_curd_1l`, `aavin_buttermilk_200ml`, `aavin_ghee_200ml`, `aavin_ghee_500ml`, `aavin_paneer_200g`, `aavin_butter_100g`, `arun_icecream_box`. Units: `L` (milk, curd), `pack` (buttermilk, paneer, butter), `jar` (ghee), `box` (ice cream). Products carry `packSizeL` or `packSizeG`.
  Demo shop id: `murugan_dairy`. Supplier ids: `aavin_vendor`, `sakthi_vendor`, `arun_distributor` (phone numbers come from `.env` → seed script).
- **Spoken hints use ONE mechanism: `aira_live.i18n.t(key, lang)`.**
  - Vision aim hints use keys `vision.aim.{move_back,spread_out,show_items,show_label,hold_closer,not_visible}`.
  - Cash hints use keys `cash.*`, e.g. `cash.spread_notes`.
  - Sarmitha adds these keys to `i18n/{en,ta,hi}.json`.
  - `aira_live.vision.hints.hint_text(key, lang)` is only a thin wrapper that returns `i18n.t(key, lang)`.
  - Result models carry the key (`aim_hint` / `hint_key`), and tools speak `t(key, lang)`.

## Analytics and ops contracts (from `saravana/02`)

**Event payloads** (`analytics.events.publish`). The business services publish AFTER a successful commit:

| Topic | Required fields |
|---|---|
| `sales` | one message per sale line: `shop_id, sale_id, sku, qty` (+ `unit_price`, `ts`) |
| `inventory-movements` | `shop_id, txn_id, sku, delta, reason` |
| `orders` | `shop_id, order_id, state` |
| `discrepancies` | `shop_id, delivery_id, field` (+ `expected`, `actual`) |
| `alerts` | `shop_id, kind, message` |

**Business fields** (Kanish):
- `business.sales.create` sets `createdAt`, and `complete` sets `completedAt` (both server timestamps).
- `business.expiry.scan` returns dicts with `sku`, `name`, `qty`, `daysLeft`.

**Routes and modules** (Saravana):
- **Routes:** `POST /jobs/expiry`, `/jobs/day-summary`, `/jobs/forecast-refresh` (OIDC; env `AIRA_JOBS_AUDIENCE`, `AIRA_SCHEDULER_SA`), and `POST /fcm/register {idToken, fcmToken}` (Ishwarya's family mode calls it).
- **`aira_live.fcm`:** `register_token`, `family_tokens`, `send_to_family`.
- **`aira_live.remote_config`:** `flag(name, default)`, `get_override(role)`. `model_for` priority is env > Remote Config > default.
- **WhatsApp gating:** the channel is gated by `remote_config.flag("whatsapp_enabled", True)`. Env/secret names: `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_ID`, `WHATSAPP_VERIFY_TOKEN`, `TELEGRAM_TOKEN`.

**BigQuery:**
- views `aira.sales_dedup`, `aira.inventory_movements_dedup`, `aira.daily_sales`
- model `aira.demand_arima`
- `reorder_suggest` only suggests, returning `next_tool: "order_create"`

**Firestore rules:**
- `shops/murugan_dairy/**` is readable by any signed-in user (judges, anonymous auth).
- All client writes are denied; the server writes via the service account.

## Messaging and wiring (from `kanish/02`)

- **`aira_live.messaging.webhooks.router`:** a FastAPI router that Saravana mounts in `main.py`. It serves `/webhooks/whatsapp` (GET verify + POST, signature checked with `WHATSAPP_APP_SECRET`) and `/webhooks/telegram`.
- **Non-blocking Live tools:** `delivery_count` and `sale_pay`.
- **Server-only Firestore collections:** `shops/{shopId}/msgIndex`, `shops/{shopId}/contactIndex`.
- **`OPEN_URL` link hand-off:** a `state` message whose `summary` starts with `OPEN_URL <url>` tells the app (Ishwarya) to open a click-to-chat or `tel:` link. Only `https://wa.me/`, `https://api.whatsapp.com/` and `tel:` are allowed.
- **`business.catalog.to_selling_units(product_doc: dict, qty: float, unit: str) -> tuple[float, str]`** (Kanish 01), e.g. 2 × `sakthi_curd_500ml` with `unit="pack"` → `(1.0, "L")`.

## Runtime contracts (from `saravana/01`)

- **`aira_live.ids.current_idem_key() -> str`:** every tool that commits (Kanish, Sarmitha) gets its idempotency key from here. It derives from the current tool-call id. Never build your own key.
- **Other names:**
  - `aira_live.session.current_tool_call_id: ContextVar[str]`
  - `Session.tool_results: list[dict]` (the safety checker compares spoken numbers against these)
  - `aira_live.tool_runtime.wrap_tool(fn, session)`
- **Auth:** `aira_live.auth.verify_hello(id_token, uid, shop_id, mock) -> AuthResult(uid, shop_id, role)`, with `DEMO_SHOP` = env `AIRA_DEMO_SHOP`, default `"murugan_dairy"`.
- **Deploy:** `aira-live` runs with `--min-instances 1 --max-instances 1`, because the session registry is in-process.

## WebSocket protocol (`packages/contracts/src/messages.ts` ⇄ `aira_live/contracts.py`)

Coordinates: point `[y, x]`, box `[ymin, xmin, ymax, xmax]`, normalized 0–1000. Audio: client 16 kHz PCM16 base64; server 24 kHz PCM16 base64.

```ts
type Lang = "ta" | "hi" | "en";  type Verbosity = "short" | "detail";
type FramePurpose = "ask" | "count" | "point" | "identify" | "invoice" | "cash" | "guide";
type ClientMsg =
  | { t: "hello"; uid: string; idToken?: string; shopId: string; lang: Lang; verbosity: Verbosity; appVersion: string; resume?: string }
  | { t: "audio"; pcm16: string }
  | { t: "frame"; id: string; jpeg: string; w: number; h: number; ts: number; purpose: FramePurpose }
  | { t: "text"; text: string }
  | { t: "event"; name: "visibility" | "network" | "fingertip_in_target"; data: Record<string, unknown> }
  | { t: "confirm"; id: string; answer: "yes" | "no"; value?: string }
  | { t: "stop" };
type CueName = "ack" | "thinking" | "done" | "warn" | "match" | "mismatch" | "unsure" | "interrupted" | "reconnect" | "offline";
type Entity = "order" | "delivery" | "sale" | "payment" | "inventory";
type ServerMsg =
  | { t: "ready"; sessionId: string; resume: string; mock: boolean }
  | { t: "audio"; pcm24: string }
  | { t: "transcript"; role: "user" | "aira"; text: string; final: boolean }
  | { t: "request_frame"; purpose: FramePurpose; burst?: { count: number; intervalMs: number }; continuous?: boolean; stop?: boolean }
  | { t: "target"; frameId: string; label: string; point: [number, number]; box?: [number, number, number, number]; confidence: number }
  | { t: "count"; sku: string; counted: number; expected: number | null; final: boolean; confidence: number }
  | { t: "state"; entity: Entity; id: string; state: string; summary: string }
  | { t: "confirm"; id: string; kind: "order" | "payment" | "sale" | "discrepancy" | "generic"; prompt: string }
  | { t: "cue"; cue: CueName }
  | { t: "error"; code: "network" | "model_timeout" | "camera" | "permission" | "unsupported" | "internal"; say: string };
```
